Each milestone needs Nilo's OK before it starts and an explicit OK after review before the next one starts (see `AGENTS.md`).

| 11 | Refinement before the integration, from bor0's review in WordPress/wordcamp.org#2286 and Nilo's answer there (decided by Nilo). No second line (decided by Nilo: very long texts are usually people adding their company, job or handle to the name). (2) Separators left over by an empty variable ("· Italy") are removed when the text is filled in, with no separator setting in the interface (decided by Nilo). (3) Changing the print size warns about elements left past the edge. (4) Bug: only the predefined variables and the event's questions become variables, not any other export column. (5) A filter by CampTix admin flag when generating the PDF, for example only the volunteers; no filter by ticket type (decided by Nilo). (6) Name normalization keeps names like O'Brien, McDonald or le Van, with rules based on patterns, and tests. (7) A stress test at flagship size (thousands of invented attendees), measuring time and memory. (8) A mark for the lanyard hole: a small vertical line at the top center to help punch the hole, with no set distance from the edge (asked for by Nilo). (9) Translations and documentation polished. (10) Plugin Check on the built plugin from the `dist` branch; the plugin is not going to the WordPress.org directory, so directory-only findings are noted and left, and anything about security or good practice gets fixed. (11) Page Up and Page Down go to the previous and next attendee, except while typing in a field. (12) pdf-lib, only used by Preview badge and Generate PDF, leaves the main bundle and loads with a dynamic `import()`; PDF.js and fontkit stay. | Done, waiting for Nilo's review |
| 12 | Before the integration pull request, from bor0's second review in WordPress/wordcamp.org#2286 (decided by Nilo). | 13 | Names in other scripts, from bor0's third review in WordPress/wordcamp.org#2286 (decided by Nilo): Inter has no CJK, Hangul, Indic, Arabic, Hebrew or Thai, and the PDF printed missing-glyph boxes with no warning. (1) Bug: an Indic font left the editor blank; the editor now loads WordPress's `regenerator-runtime`, which fontkit's Indic shaper needs. (2) Every attendee's text is checked against the font of each text box. (3) Automatic fallback in a fixed order (decided by Nilo, replacing the milestone 14 that was planned, a fallback font chosen per script, which would add nothing): the box's font, then Inter, then the Noto font of the script when installed in the Font Library, active or not, at the closest weight, on the canvas and in the PDF; each text uses one font, never a mix. (4) A warning under the font selector, as a checklist: the attendees no font can print yet, and by script the Noto font to install, in green with a check when an installed one already prints them; it goes once nothing is left. The sandbox installs Noto Sans JP, inactive, to show a script already solved. The Attendees panel has a table of scripts with the font that prints each or the one to install, and lists the attendees left, like cut text; the Generate PDF summary counts them. (4b) The canvas shows those characters as the PDF prints them, as empty boxes, never filled in from a system font, and marks the box in red (asked for by Nilo). (5) Cut text is cut between whole characters as a reader sees them, so an Indic syllable is never split. (6) JavaScript tests for this with the Noto fonts the Font Library installs. (7) The guide, the specification, the decisions and the integration checklist (the local Docker setup of WordPress/wordcamp.org, as bor0 suggested). No Noto font is bundled: the CJK ones alone would add 25–30 MB. Checked on the sandbox with five attendees renamed in the browser (Japanese, Korean, Hindi, Arabic, Polish). (8) The sandbox, and so the public demo, has 13 invented attendees with names in other scripts (asked for by Nilo): Japanese, Korean, Hindi, Arabic, Chinese, Tamil, Hebrew, Thai, Greek, Cyrillic, and Polish and Turkish for the Inter fallback; with the sample design in Inter and Noto Sans JP installed, the two Japanese ones print with it and the editor warns about the other 7. | Done, waiting for Nilo's review |

- The editor lives inside the normal WordPress admin: the admin bar and the admin menu stay.
- A toolbar on top: add element (+), undo and redo, then the attendee pagination (‹ number of total › and the attendee's name), all aligned to the left so the pagination does not move with the length of the name (changed by Nilo after milestone 6); the save state ("Saved"), Preview badge and Generate PDF on the right. No title.
- The canvas in the center, with only the badge.
- A fixed right sidebar with two tabs. Document: Background, Print size, Elements, Attendees and Import/Export Design (JSON; renamed from Design by Nilo). Element: the properties of the selected element.
- Generate PDF opens a dialog with the page range.
