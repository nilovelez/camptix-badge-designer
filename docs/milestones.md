# Milestones

Each milestone needs Nilo's OK before it starts and an explicit OK after review before the next one starts (see `AGENTS.md`).

| # | Milestone | Status |
|---|---|---|
| 0 | Plugin skeleton and development setup: main file, readme, Playground blueprint, Studio site, WPCS, Guppy. | Done |
| 1 | Technical spike: an admin page that generates a 300-page badges PDF in the browser with pdf-lib (Inter embedded, vector QR codes from LadyQR, Gravatars, a vector PDF background, crop marks) and measures it; PDF.js preview; WOFF2 check. Confirms or changes the proposals in `docs/decisions.md`. | Done |
| 2 | Attendee data: PHP reads the CSV in `test-data/`, sorts by `Attendee ID`, validates usernames, normalizes names and sends the browser only the allowed fields. | Done |
| 3 | Editor structure: the Badges admin page becomes the editor of the mockup, inside the normal admin (admin bar and menu stay); background from the Media Library (PDF, PNG or JPG) with size detection, print size, bleed and safe area (5 mm by default), guides, design saved automatically. The spike moves to Badges › Technical test. | Done |
| 4 | Elements and text boxes: the four default elements; select, drag, resize, snap, nudge and delete; the + inserter and the Elements list; text boxes with variables, font (Inter and the Font Library), weight, size, color from the site palette, alignment and uppercase; text that does not fit is cut, with a warning (no shrink to fit, decided by Nilo); QR codes and Gravatars drawn with real data; attendee pagination; undo and redo. | Done |
| 5 | QR code and Gravatar options: Gravatar shape (round or square) and fallback (none, generated by Gravatar, or a fixed image from the Media Library, drawn by the plugin); QR codes at least 20 × 20 mm. | Done |
| 6 | PDF generation in the browser: one-page preview shown in the editor; Generate PDF with all pages or a range, a summary, progress and cancel; crop marks. The technical test page is removed. | Done |
| 7 | Export and import of the design as JSON; review: left-aligned pagination, uninstall cleanup, readme with privacy notes; Plugin Check clean on a release-like copy. The release zip is postponed to the backlog (decided by Nilo). | Done |
| 8 | WordCamp sandbox and live CampTix attendees: the Playground site installs the real CampTix from `WordPress/wordcamp.org`, with an mu-plugin that stands in for the few WordCamp.org functions it calls and creates tickets, questions and invented attendees. The plugin reads `tix_attendee` live when CampTix is active (the CSV stays as the fallback), and the event's questions come from `tix_question`. When CampTix is active, the editor moves to Tickets › Badge Designer; without it, it stays as Badges in the main menu (decided by Nilo). The official badge generator is not installed in the sandbox (decided by Nilo). See "Name, and the road to WordCamp.org" in `docs/decisions.md`. Checked: CampTix's own CSV export of the sandbox, through the CSV reader, gives exactly the live list; the full PDF (139 badges) has the right names, question answers and QR codes on every page. | Done |
| 9 | Public demo: a GitHub Action builds the plugin on every push to `main` and publishes it, ready to install, to a `dist` branch (decided by Nilo); a Playground link anyone can open, with the WordCamp sandbox, the plugin from `dist` and a sample design ready to print, on the WordCamp Europe 2025 badge background (provided and laid out by Nilo), opening on Matt Mullenweg's badge, the first attendee, with his public Gravatar and username (decided by Nilo). Also: a loading bar while the editor loads, the editor fixed to the window, a transparent background option for QR codes, the Design panel renamed Import/Export Design (all asked for by Nilo), and a fix for the editor going blank. | Done, waiting for Nilo's review |
| 10 | Present it (decided by Nilo), in this order: the user guide for organizers and testers, one page on GitHub Pages (`guide/`), meant to replace the badge pages of the WordCamp Organizer Handbook; the README with the technical side; a new issue in WordPress/wordcamp.org with the proposal and how to test it; a comment on PR #2278 asking to close it and pointing to the issue; and a proposal on the Make/Community blog that sends the discussion to the issue. The proposal: integrate it into `camptix-badge-generator` once tested, with no alternative. Before anything goes public: the editor translatable, and a notice instead of the editor on small screens. Also asked for by Nilo: the `{username}` variable (for WordPress/wordcamp.org#1701) and folded badges (single or folded, asked when the background is chosen). | In progress |
| 11 | Refinement (decided by Nilo). First item: a smaller editor script. pdf-lib, only used by Preview badge and Generate PDF, leaves the main bundle and loads with a dynamic `import()` the first time either is used; PDF.js and fontkit stay, because the editor needs them from the start to draw a PDF background and measure text (decided by Nilo). Measured before and after on the public demo. Second item: when the CampTix email address has no Gravatar, use the one of the attendee's WordPress.org username, looked up 100 usernames per request (decided by Nilo; see "Gravatar from the WordPress.org username" in `docs/decisions.md`). | Planned |

The editor mockup is at https://claude.ai/artifact/AzEqUCXhPU5poaHuaQMDix (private to Nilo). Its final layout, approved by Nilo:

- The editor lives inside the normal WordPress admin: the admin bar and the admin menu stay.
- A toolbar on top: add element (+), undo and redo, then the attendee pagination (‹ number of total › and the attendee's name), all aligned to the left so the pagination does not move with the length of the name (changed by Nilo after milestone 6); the save state ("Saved"), Preview badge and Generate PDF on the right. No title.
- The canvas in the center, with only the badge.
- A fixed right sidebar with two tabs. Document: Background, Print size, Elements, Attendees and Import/Export Design (JSON; renamed from Design by Nilo). Element: the properties of the selected element.
- Generate PDF opens a dialog with the page range.
